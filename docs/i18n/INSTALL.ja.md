# MFD-24 のインストール

[English](../INSTALL.md) · [Français](INSTALL.fr.md) · [Deutsch](INSTALL.de.md) · [Italiano](INSTALL.it.md) · **日本語** · [中文](INSTALL.zh.md)

MFD-24 の配布方法はひとつだけ。[GitHub のリリースページ](https://github.com/amorroma1/mfd-24/releases/latest)にある署名済み `app-earth-release.apk` です。Wear OS にはサイドロード用の UI がないため、以下のどのルートも最後は ADB に行き着きます — 問題はどのマシンで実行するかだけ。ルートは三つ、簡単な順です。どれも[開発者向けオプション](#まず時計側の開発者向けオプション)が必要なので、そこから始めてください。

Wear OS 3.0 以降(API 30)が必要です。TicWatch Pro 3 Ultra(454 × 454)で開発・着用していますが、レイアウトは半径に比例するため、他の円形画面でも問題ないはずです。

## なぜ MFD-24 は Google Play にないのか

意図した決定であり、未対応の宿題ではありません。理由は三つ:

- **デッドマン・モニターを衝動インストールさせてはならない。** ビジランス機能は認証を受けていない補助手段です — それが何をするか、何を約束しないかを読んでから信頼する人にこそ役立ちます。ストアの掲載ページは 30 秒でタップされるために作られています。サイドロードは読まれ、確認され、意図を持ってインストールされる — この文字盤が作られた相手はまさにその読者です。
- **必要な権限が「高くつく」種類のもの。** バックグラウンド位置情報、身体センサー、ヘルス型フォアグラウンドサービスは、ここでは正当です — 天気の更新はバックグラウンドで走り、モニターは画面消灯中に加速度計を読みます。しかし Play では、この組み合わせが趣味のプロジェクトを商用ウェルネスアプリと同じ常時審査の機構に放り込みます。ポリシーは毎年変わり、沈黙の既定の結末は削除です。その時間は文字盤に使うほうがいい。
- **インストールするものを自分で検証できる。** すべてのリリースはノートに APK の SHA-256 を記載し、APK は 1.0.0 以来同じ鍵で署名され、それを生んだソースはタグひとつ先にあります。ストアが加えるのは仲介者であって、保証ではありません。

ライセンスの問題ではありません — GPL ソフトウェアは Play で許可されています。当直の計器を誰が、どれだけ意図を持ってインストールするかの問題です。

## まず:時計側の開発者向けオプション

1. 時計で **設定 → システム → 端末情報 → バージョン**(文言はメーカーにより異なります)を開き、**ビルド番号**を 7 回タップして開発者になったと表示させます。
2. 設定に戻り、**開発者向けオプション**を開いて **ADB デバッグ**と**ワイヤレスデバッグ**(Wear OS 3 では **Wi-Fi 経由のデバッグ**の場合あり)をオンにします。
3. 時計を、インストールを行うスマートフォンまたは PC と**同じ Wi-Fi ネットワーク**につなぎます。

## ルート 1 — スマートフォンだけで:Wear Installer 2

いちばん穏やかなルート。ADB のハンドシェイクを代行し、各手順を画面に示してくれる無料の Android アプリです。サードパーティ製フリーウェア(Wear Installer 2、Malcolm Bryant / freepoc 作)であり、本プロジェクトの一部ではありませんが、まさにこの用途で広く使われています。

1. **スマートフォン**に Google Play から **Wear Installer 2** をインストールします。
2. **スマートフォン**で[最新リリース](https://github.com/amorroma1/mfd-24/releases/latest)から `app-earth-release.apk` をダウンロードします。
3. Wear Installer 2 のウィザードに従います。時計の IP アドレスとペアリングコードを求められます — どちらも時計の**開発者向けオプション → ワイヤレスデバッグ → 新しいデバイスとペア設定**にあります。
4. ダウンロードした APK を指定してインストールさせます。
5. 時計側:現在の文字盤を長押しし、**MFD-24** までスワイプしてタップします。

## ルート 2 — ADB の入った PC

正統ルート。ほかのすべてはこれの糖衣にすぎません。

1. [Android platform-tools](https://developer.android.com/tools/releases/platform-tools)(小さな zip で、中に `adb` が入っています)を入手し、[最新リリース](https://github.com/amorroma1/mfd-24/releases/latest)から `app-earth-release.apk` をダウンロードします。
2. *(10 秒の価値はあります)* ダウンロードをリリースノート記載の SHA-256 と照合します。Windows では `certutil -hashfile app-earth-release.apk SHA256`、macOS/Linux では `shasum -a 256 app-earth-release.apk`。
3. 時計側:**開発者向けオプション → ワイヤレスデバッグ → 新しいデバイスとペア設定**。IP と**ペアリング用ポート**、6 桁のコードが表示されます。そのダイアログが開いている間に:

   ```
   adb pair 192.168.1.50:37000 123456
   ```

4. ワイヤレスデバッグのメイン画面に戻ると、時計は**別の**ポート — 接続用ポート — を表示しています:

   ```
   adb connect 192.168.1.50:41234
   adb install -r app-earth-release.apk
   ```

5. アクティブな文字盤にします — 時計の文字盤ピッカーで選ぶか、次を実行:

   ```
   adb shell am broadcast -a com.google.android.wearable.app.DEBUG_SURFACE \
       --es operation set-watchface \
       --ecn component com.avdesign.mfd24/com.avdesign.mfd24.MfdWatchFaceService
   ```

うまくいかないとき(必ず一度は起きます):

| 症状 | 原因と対処 |
|---|---|
| `adb connect` が失敗するか固まる | **ペアリング用**ポートを渡しています。接続用ポートはワイヤレスデバッグのメイン画面にある別の番号です。 |
| `protocol fault (couldn't read status message)` | ペアリングコードがダイアログと共に失効しました。**新しいデバイスとペア設定**を開き直し、表示されている間に `adb pair` を実行してください。 |
| コマンド途中で `error: closed` や `device offline` | 画面が眠った時に時計が Wi-Fi から落ちました。画面を起こして再接続を — ワイヤレスデバッグを入れ直した場合は**新しいポート**を想定してください。 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | インストール済みビルドと署名鍵が異なります(自前ビルドの上にリリース、またはその逆)。先にアンインストールを — 設定も一緒に消えます。 |

## ルート 3 — ソースからビルド

読むため、手を入れるため、あるいは自分のバイナリしか信じないために。

```
git clone https://github.com/amorroma1/mfd-24.git
cd mfd-24
./gradlew :app:assembleEarthDebug
adb install -r app/build/outputs/apk/earth/debug/app-earth-debug.apk
```

JDK 17 以降(`JAVA_HOME` を Android Studio 同梱のものに向ければ十分)と Android SDK が必要です。`assembleEarthRelease` はリリースバリアントをビルドします。署名鍵が未設定ならデバッグ用キーストアにフォールバックし、それでも自分の時計にはインストールできます。

**署名が境界です。** 自前ビルドの APK と GitHub のリリースは互いに上書きインストールできません。Android は更新に同じ署名鍵を要求するからです。乗り換えるにはまずアンインストールが必要で、設定・当直状態・インシデントログも一緒に消えます。レーンを選んでください — 着用にはリリース、いじるには自前ビルド — そしてそこに留まること。

## 更新

新しいリリースがあることは時計が知らせます。インストールはしません——できるふりもしません。

- **1 日 1 回、当直外に、GitHub へ「もっと新しいものはあるか」と尋ねます。** 読むのは小さな JSON だけ。**ダウンロードは一切しません。** 当直中は走らず、**ABOUT → RELEASE CHECK** で全部止まります。
- **リリースごとに通知は一度だけ。** 待っているリリースは **ABOUT → RELEASES** が名前で示します。
- **タップするとリリースページが QR コードで出ます。** スマートフォンを向けてください。ノート、SHA-256、APK はすべてそのページに、ブラウザで、読める大きさで載っています。
- **あとは普通に、PC から入れます:**

  ```
  adb install -r app-earth-release.apk
  ```

**なぜ時計からではないのか。** Wear OS が許さないからです。セッションは通り、プラットフォームが確認を求め、その純正インストーラーが *「Install/Uninstall actions not supported on Wear」* と答えます——API 30 エミュレーターと Wear 3.5 の TicWatch Pro 3 Ultra で確認済み。抜け道はすべて通常のアプリには閉じています。

## インストール後

- **設定**は文字盤の長押し → 鉛筆アイコンの先にあります。文字盤が必要とするものはすべてそこで求められます — 天気・Nadir・サイトロックのための位置情報、権限が要る読み出しをスロットに選んだ瞬間のセンサー権限。インストール時には何も要求されません。権限の全表は [README](../../README.md#permissions) にあります。
- **更新**は自動で知らせてくれます — 上の[更新](#更新)を参照。新しいリリースでの `adb install -r` も常に有効です。設定はどちらでも生き残ります。ただし設定スキーマを変えるリリースは例外で、その場合はリリースノートに明記されます。
- **コンパニオンアプリなし、アカウントなし。** APK が製品のすべてです。
