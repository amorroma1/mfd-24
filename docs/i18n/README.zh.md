# MFD-24

*Multi-Function Display，24小时：驾驶舱的显示屏，以及时针一圈的一天。*

[![build](https://github.com/amorroma1/mfd-24/actions/workflows/build.yml/badge.svg)](https://github.com/amorroma1/mfd-24/actions/workflows/build.yml)

[English](../../README.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Italiano](README.it.md) · [日本語](README.ja.md) · **中文**

为值班值更的人而造的24小时仪表盘 —— 飞行员、船员、无人机机组、值班军官。时针一天转一圈，你的当班画成这一天上的一段弧，一个会逐级升级为SOS并留下记录的失能告警（dead-man）监视器，以及值班真正依赖的遥测。

除天气外一切都可离线工作。没有配套App，没有账号，没有数据统计。GPL。

## 你得到什么

| | |
|---|---|
| **24小时表盘** | 一天一圈。正午在上或午夜在上。分针走自己的分度环；秒是一个逐格跳动的游标，没有任何东西扫过表盘。 |
| **值班计时器** | 立即开始或预约开始。一段弧横跨当班的小时，随着值守逐渐变暗；`DUTY: 04:40 REM` 倒计时。起止两端都有声音与震动提醒，熄屏也不例外。结束的班次一小时后自行清除。 |
| **警戒监视** | 默认关闭。每5/10/15分钟要求一个生命信号；三十秒后以脉冲方式发出SOS，并把 `MAN DOWN` 与事发的Zulu时刻留在表盘上。可选：未应答检查期间的脉搏，与表盘在此之前的最后一次读数对照。 |
| **Zulu + 日期时组** | `Z 22AUG 12:16`，写日志条目所用的时钟。 |
| **天气** | 温度、METAR式天气现象与QNH。在机场显示该场站**自己的METAR**；其他任何地方用Open-Meteo。每30分钟刷新。 |
| **5公里站点锁定** | 从194 KB设备端索引中的9,649个站点里报出最近的机场、港口、直升机场或发射场。军事设施以强调色绘制。 |
| **Nadir、太阳与月亮** | 日照时段在时圈上着色，离线计算。太阳与月亮位于各自真实的时角 —— 把标记对准天上的实物，表盘就是一具**罗盘**。月亮带着真实的月相。 |
| **传感器插槽** | 表心旁两个可选读数：心率、平台自己的每日步数总计，或测站气压。默认关闭；只在亮屏时运行。常亮显示下，佩戴时每分钟重读一次脉搏 —— 十五秒窗口，三分钟未锁定则显示短横。 |
| **常亮显示** | 同一张表盘，调暗。`AUTO` 在日落后将其减淡为隔一个像素 —— 夜班期间绝不减淡。 |
| **直接启动** | 手表解锁之前就画出带数据的表盘。 |

## 安装

从[最新版本](https://github.com/amorroma1/mfd-24/releases/latest)下载 `app-earth-release.apk` 并侧载。Wear OS 没有侧载界面，所以这是一件 ADB 的活：

```
adb connect 192.168.1.50:41234
adb install -r app-earth-release.apk
```

然后在手表自己的表盘选择器里选 MFD-24。
**[完整指南 —— 三条路线，从『只用一部手机』到从源码构建 →](INSTALL.zh.md)**

<details>
<summary><b>更新，以及为什么不上架 Google Play</b></summary>

<br>

手表**每天一次、非值更时**查询 GitHub，每个版本只提醒你一次。它什么都不下载、什么都不安装：**Wear OS 不允许应用安装应用**（在 TicWatch Pro 3 Ultra 上已验证）。`ABOUT → RELEASES` 把发布页显示为二维码供手机相机扫描，安装仍然是 `adb install -r`。`ABOUT → RELEASE CHECK` 可把整件事关闭。

不上架 Google Play 是有意为之：失能告警监视器不应该被冲动安装；它名正言顺需要的权限会把一个业余项目置于永久的商店审查之中；而一个在发布说明中附有 SHA-256 的 APK 比商店条目更可验证。完整理由见 [INSTALL.zh.md](INSTALL.zh.md#为什么-mfd-24-不上架-google-play)。

</details>

<details>
<summary><b id="permissions">权限 —— 安装时不索取任何权限</b></summary>

<br>

定位权限在设置界面索取，因为表盘是一个 `WallpaperService`，自己无法弹出对话框。

| 权限 | 用途 | 没有它 |
|---|---|---|
| `ACCESS_FINE_LOCATION` | 天气、Nadir、站点锁定 | 这三项空白；时钟与天文计算不受影响 |
| `ACCESS_BACKGROUND_LOCATION` | 同上，但来自每30分钟的刷新任务 | 平台返回 null 而不是错误，看起来与没有信号一模一样 |
| `WAKE_LOCK`、`FOREGROUND_SERVICE_HEALTH` | 警戒监视器，它必须在熄屏时持续感知 | 仅影响该功能 |
| `VIBRATE` | 班次起止与SOS | 起止无声 |
| `SCHEDULE_EXACT_ALARM` | 起止准点落在整分 | 会申请但**非**必需；没有它，起止可能偏差几分钟 |
| `INTERNET` | 每30分钟的 Open-Meteo 与 METAR，以及每日一次的版本检查 | 没有天气，没有版本检查 |
| `BODY_SENSORS` | 心率插槽与事件中的脉搏 | 短横；不提供 `LOG PULSE` 行 |
| `ACTIVITY_RECOGNITION` | 步数插槽；在 Wear 5+ 上也是警戒服务得以启动的条件 | 短横；在较新的 Wear 上没有警戒监视 |
| `POST_NOTIFICATIONS` | 监视器的持续通知，以及每个版本一次的更新通知 | 监视器静默运行 |

不读联系人，不读存储，除上述调用外不触网。手动输入的位置可以完全取代定位 —— 见设置中的**位置**。

</details>

<details>
<summary><b>脚注 —— 步数、所需硬件，以及它有多重</b></summary>

<br>

**步数是怎样得出的。** 该行优先采用平台自己通过 Health Services 给出的每日数字，因为那是手表其余部分所认同的数字，而且它不在乎这块表盘是何时安装的。若手表没有这样的提供者，或提供者绑定后便再无回音，表盘就自己从硬件计步器计数。这一回退**从下一个本地午夜起**是精确的，因为计数器的值在日界处被记录下来；在安装当天，它只能从你打开该插槽的那一刻起计数，并且显示短横而不是一个它凭空编出来的 `0`。这里测试的一块手表把它的"每日"总计报成自订阅开始以来的步数，而不是自午夜以来的 —— 这是提供者的怪癖，不是设置，也是这一行值得当作*已计步数*而非健身统计来读的原因。

**屏幕。** 圆形，在 **454 × 454** 上测试。表盘上每个位置都是半径的一个分数，所以其他圆形尺寸应该没问题；方形和带"下巴"切边的屏幕不在设计之内，会裁掉外圈刻度。文字也按半径定大小 —— 读数宽度预算是一道算术，并有一条测试会在任何一行碰到小时数字时失败。

**硬件与性能。** Wear OS 3.0+（API 30），平台能跑的任何手表；除普通画布外不需要任何 GPU 特性。`render()` 不分配任何内存，因此没有需要绕开安排的垃圾回收停顿，帧率按需驱动：**静止时每秒一帧**，仅在过渡动画期间为16 ms，常亮显示下每分钟一帧。可选传感器是唯一真正的开销 —— 心率是一枚LED，而警戒监视器让加速度计在传感器中枢里批量缓存，而不是唤醒处理器。其余一切都靠缓存值运行。

**大小。** 安装后约 **3.5 MB**，其中代码约 2.8 MB，设备端站点索引 190 KB，选择器预览 220 KB。索引有意不压缩存储，以便无需解包即可读取。仅含英文资源：应用自身的文字是英文，而携带八十种它永远显示不了的库字符串语言包要多花 260 KB。

</details>

## 它不是什么

个人仪表，而非经认证的仪表。警戒监视器是未经认证的辅助手段：它可以被关闭，会被松动的表带暂停，也会被平台自身的休眠限制延迟。事件日志只覆盖**一次值班** —— 开始另一次值班就会清空它，所以任何值得保留的东西都要先经 `EXPORT LOG` 导出。这里没有任何东西可以替代监管机构批准的设备。

<details>
<summary><b>导出事件日志 —— 两条通道及其限制</b></summary>

警戒分区中的 `EXPORT LOG` 把日志放到手表真正拥有的两条通道上：给已经对准它的手机相机的**二维码**，以及**声音** —— Bell 202 AFSK，1200 Bd，8N1，APRS 所用的物理层，所以接收端是贴在表壳上的 `minimodem --rx 1200`。两者携带同一份纯文本数据包：一个头部、仪表的呼号、一行带班次起止与时长的 `WATCH`、每行一条以Zulu时间记录的事件 —— `LOG PULSE` 开启时附 `HR` 与 `BASE … AT` —— 以及一行 `END`，带有条目数和其上全部内容的 CRC32，这样一张模糊的照片或一段嘈杂的录音会大声失败，而不是悄悄丢掉一行。

- **日志保留当前值班最新的 32 条事件**，最多 30 天。开始下一次值班会清空它；先导出。
- **声音始终携带完整日志** —— 到上限时是十八秒的音调。传输在屏幕打开时开始，点一下重播。
- **二维码携带能装进最大码的最新条目**，即 1.2 英寸屏幕所能显示的最大二维码：各行仅为时刻时全部 32 条，每行都带脉搏及其参照时约 14 条。被截断的码会明说 —— 其 `END` 行读作 `END 14 OF 32`，绝不是 `END 14`。要取得那么长的日志的每一行，用声音。
- **只读。** 没有导入路径，所以任何读取数据包的东西都写不了记录。

</details>

## 构建

```
git clone https://github.com/amorroma1/mfd-24.git
cd mfd-24
./gradlew :app:assembleEarthDebug
```

JDK 17+ 与 Android SDK。192 条 JVM 测试：`./gradlew :app:testEarthDebugUnitTest`。

## 它是怎样做出来的

由一个人设计、决定并佩戴，代码与 Claude（Anthropic）结对编写。凡能测量的常量都在手表上实测而非推算，每条不变量都由测试钉住，没有在手腕上跑过的东西不会发布。`CLAUDE.md` 中的工作笔记是这次协作的记录，有意保留在仓库里。
